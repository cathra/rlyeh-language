# 8. 内存管理：分层所有权模型

> C 程序员最头疼的事，十件里有七八件和内存有关：`use-after-free`、重复 `free`、内存泄漏、野指针、数据竞争。Rlyeh 的目标很明确——**把这些 bug 在编译期消灭，而且不付出运行时 GC 的代价**。
>
> 做法是一套**分层内存模型**：从零开销的"编译期所有权"一直到"可选的 GC"，逐级递进。默认是 L0（零开销），GC 是"最后一招"。
>
> **读者背景假设**：本文专门写给有 C 基础、无 Rust/Rlyeh 经验的读者。你会看到大量 `// C` 对照片段，帮你把"Rlyeh 怎么保证安全"映射到"我在 C 里是怎么手动保证（或没保证）的"。

---

## 8.1 心智模型：四层内存

| 层级 | 机制 | 关键字 | 运行时开销 | 适用场景 |
|------|------|--------|------------|----------|
| **L0** | 静态所有权 + 借用 + 生命周期 | `let`、`&`、`&mut` | 零开销 | 绝大多数值（栈 + 堆所有权） |
| **L1** | 区域（Region） | `region 'r {}`、`in 'r`、`transfer` | 零开销（批量释放） | 一批"同生共死"的对象 |
| **L2** | 引用计数 | `Rc<T>`、`Arc<T>` | 原子操作 | 多处共享所有权 |
| **L3** | 可选 GC | `Gc<T>`（插件式） | GC 停顿 | 图结构 / 循环引用 |

```rlyeh
// 自上而下：越往下越"自动化"，也越有运行时成本。默认从 L0 开始。
```

> **C 对照**：
> - L0 ≈ "编译期检查过的栈/值语义 + 借用"——本质上就是你写 `int x;`（栈上、出作用域自动失效）的**安全推广版**，但也能管堆对象。
> - L1 ≈ 你手写的 **arena 内存池**（`malloc` 一批、最后 `free` 一次）。
> - L2 ≈ 你手写的 **refcount 结构体**（`struct { T val; int refcnt; }` + 加减引用）。
> - L3 ≈ 可选的**保守 GC**（如 Boehm）。
>
> 关键区别：**默认 L0 零开销，和 C 同一性能档**；安全来自编译期分析，不来自运行时托管。

## 8.2 L0 所有权与借用（默认，零开销）

Rlyeh 里每个值都有**唯一所有者**。所有者在作用域结束时自动释放（确定性析构，类似 C++ RAII，但不需要你写析构函数）。`&`/`&mut` 让你**借而不取**——只读或临时修改，不转移所有权。

```rlyeh
fn main() {
    let x = 10;
    let r = &x;            // 不可变借用（不获取所有权）
    println(*r);           // 10

    let mut y = 20;
    let m = &mut y;        // 可变借用
    *m = 21;               // 经 * 写回
    println(y);            // 21

    // x / y 离开作用域时自动释放，无需 free
}
```

**严格借用检查**（对应 Rust 的 E0502/E0499/E0596/E0597）：
- `&mut` 与任何活跃借用**互斥**；多个 `&mut` **互斥**（同一时刻只能有一个可变借用）。
- `&mut` 要求被借用者用 `let mut` 声明。
- 局部引用逃逸出函数（返回 `&x`）报 `DanglingReference`。

> **语义有意宽松**：读取被借用变量、经 `*p` 写入是允许的（裸指针别名合法）；多个共享借用 `&` 可共存；**只有"直接赋值给被借用变量"才触发冲突**。`print`/`println` 的引用参数会自动剥层打印（`println(r)` ≡ `println(*r)`）。这比 Rust 严格版宽松，更贴近 C 程序员的直觉，同时仍挡住绝大多数危险写法。

**生命周期标注** `'a` 语法接受、宽松检查（严格验证规划中）；`ref`/`ref mut` 模式可在 `match` 臂 / `let` 中绑定引用而非拷贝。

```rlyeh
// 函数参数里的借用：调用方持有数据，函数只"看一眼"
fn len(xs: &[i64]) -> i64 { xs.len() }   // 切片引用见 §6
```

> **C 对照**：`&x` ≈ `&x`（取地址），但 C 编译器**完全不管**你之后会不会 `free` 掉这块内存再 `x->field`，或同时持有读写两份指针造成竞争。Rlyeh 把"借用期间原主人不能改"这件事**编进类型系统**，编译器替你看门。

## 8.3 L1 区域 Region（批量释放，零开销）

当一堆对象"同生共死"（比如解析一棵树、处理一批请求），逐个 `free` 既啰嗦又慢。Rlyeh 的 **Region** 让你一次性分配、一次性释放：

```rlyeh
struct Point { x: f64, y: f64 }

fn process() {
    region 'r {                              // 开一个区域 'r
        let p = Point { x: 1.0, y: 2.0 } in 'r;   // 在区域内分配
        use(&p);
    }                                        // 离开块：区域内所有对象整体回收
}

// 把所有权"转运"出区域（区域结束时不释放它）
fn create() -> Point {
    region 'r {
        let p = Point { x: 1.0, y: 2.0 } in 'r;
        return transfer p out of 'r;
    }
}
```

三种分配策略（L3 ✅ 接线 `rlyeh-region-alloc`）：

```rlyeh
region 'r adaptive { /* 自适应初始容量（PGO 画像回灌） */ }
region 's with_size (4096) { /* 精确预分配 */ }
region 't strategy (bump) { /* 顺序分配、整体释放，最快 */ }
```

> **C 对照**：`bump` 策略就是**只维护一个指针**，分配即前移——`malloc` 的 O(1) 极致版，但只能整体批量释放。这正是你手写 arena 分配器时的常见手法，Rlyeh 把它做成了语言内建。区域完美匹配"同生共死"场景（临时缓冲区、解析中间结果）。

## 8.4 L2 引用计数（Box / Rc / Arc）

当**多处需要共享同一个值的所有权**时，用引用计数：最后一个持有者释放。

| 类型 | 机制 | C 对照 |
|------|------|--------|
| `Box<T>` | 独占堆分配（单一 owner） | `T* p = malloc(sizeof(T)); ...; free(p);` 的**安全版**（自动 free） |
| `Rc<T>` | 引用计数（单线程） | 你手写的 `struct { T v; int refcnt; }` + `retain/release` |
| `Arc<T>` | 原子引用计数（多线程） | 同上，但 `refcnt` 用原子操作（对应 C11 `atomic_int`） |

```rlyeh
fn main() {
    let b = Box::new(42);        // 独占堆对象
    println(*b);                 // 42：* 解引用自动剥层

    let shared = Rc::new(7);
    let a = shared.clone();      // 引用计数 +1
    let c = shared.clone();      // 引用计数 +1
    println(*a + *c);            // 14：三个句柄指向同一份 7
}                                // 全部离开作用域后才真正释放
```

> **C 对照**：`Rc::clone` ≈ 你手写的 `obj->refcnt++`；当 `refcnt` 归零时 `free`。Rlyeh 的 `clone` 只是加计数、**不深拷贝数据**——这正是引用计数的意义。跨线程请换成 `Arc`（原子计数），否则和 C 里多线程改 `refcnt` 一样会出竞态。

## 8.5 L3 可选 GC（Gc）

当数据结构是**带环的图**（父子互相引用，引用计数永远归不了零），用可选的保守标记-清除 GC 作为"最后一招"：

```rlyeh
gc_region {                      // 在 GC 区域内分配
    let node = Gc::new(Node::new());
    // 逃逸 root + 保守标记-清除由 rlyeh-gc-runtime 负责
}
```

> **C 对照**：≈ 你接入 Boehm GC 这类保守收集器。Rlyeh 默认**不开启** GC——绝大多数场景 L0/L1/L2 就够，且零 GC 停顿。只有遇到循环引用、或你懒得手工管理生命周期时，才把对象放进 `Gc`。

---

## 8.6 怎么选：决策表

| 你的需求 | 选哪层 | C 里的对应做法 |
|----------|--------|----------------|
| 一个短生命周期的值（算完就扔） | **L0** 栈/值语义 | 局部变量 `int x;` |
| 一批对象同生共死 | **L1** Region | 手写 arena 分配器 |
| 多处共享、无环 | **L2** `Rc`/`Arc` | 手写 refcount 结构体 |
| 图 / 循环引用 | **L3** `Gc` | Boehm GC 或手动破环 |
| 需要"指针但编译器管安全" | **L0** `&`/`&mut` | `T*` + 你自己的纪律 |

> **一句话**：Rlyeh 把 C 程序员"凭经验选内存策略"的过程，变成了**语言内建、编译器强制**的默认行为——默认安全（L0），需要时才升级到更自动的层。
