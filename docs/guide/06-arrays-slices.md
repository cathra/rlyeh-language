# 6. 数组、Vec 与切片

> 本章目标：搞懂 Rlyeh 里三种"连续容器"——**数组（array）**、**动态向量（Vec）**、**切片（slice）**——分别是什么、怎么用、互相怎么转换。这是从 C 的"数组即指针"思维过渡到 Rlyeh 安全容器模型的关键一章。

---

## 6.1 数组 `array`：长度固定的连续容器

数组在栈上（或作为结构体字段）分配，长度在编译期确定，元素类型统一：

```rlyeh
let arr = [10, 20, 30];                 // 类型推断为 [i64; 3]，长度 3 写死在类型里
let arr2: [i64; 4] = [1, 2, 3, 4];      // 类型注解显式标注长度
let x = arr[0];                         // 索引读取（从 0 开始，和 C 一致）
arr[1] = 99;                            // 索引写入（若 arr 为 let mut）
let ch = s[0];                          // 字符串按字符索引（步长 1 字节）
```

> **C 程序员的视角**：
> - Rlyeh 的 `[i64; 4]` 等价于 C 的 `int64_t arr[4];`——**长度是类型的一部分**，编译期固定。
> - 索引从 0 开始、`[]` 运算符、`arr[i]` 读写——这些和 C 完全一样。
> - **关键区别**：Rlyeh 的数组赋值/传参默认是**整体值拷贝**（因为值语义）；而 C 的数组名会退化成指针。Rlyeh 里 `let b = arr;` 会得到 `arr` 的完整副本，两个数组互不影响。如果需要"共享同一份"，用引用 `&arr` 或 `Vec`。

### 数组 vs C 数组

| 维度 | C 数组 | Rlyeh 数组 `[T; N]` |
|------|--------|----------------------|
| 长度 | 编译期（但常退化成指针丢失长度） | 编译期，且**永远保留在类型里** |
| 传参 | 退化为指针，长度信息丢失 | 默认整体拷贝；或用 `&[T]` 切片传递 |
| 越界 | 未定义行为（静默） | 编译期可查部分越界；运行时越界安全处理 |
| 返回 | 不能直接返回数组（要 malloc） | 可以直接返回（值拷贝） |

## 6.2 动态向量 `Vec<T>`：运行时可变长度

当长度在编译期未知、或需要增长时，用 `Vec`（类似 C++ 的 `std::vector`、Go 的 slice、Python 的 list）：

```rlyeh
let v = Vec::new();              // 空向量（元素类型由后续使用推断）
v.push(10);                     // 追加
v.push(20);
let n = v.len();                // 长度：2
let first = v[0];               // 索引读取

let v2 = vec![1, 2, 3];         // 字面量构造（vec! 宏）
```

> **C 程序员的视角**：`Vec` 内部就是 C 里你常手写的"指针 + 长度 + 容量"三元组，外加**自动 realloc 增长**和**自动释放**（不用你 `free`）。Rlyeh 的 `Vec` 在离开作用域时由编译器插入释放逻辑，不会内存泄漏。
>
> **和数组的区别**：`Vec` 长度运行时可变、存在堆上；数组长度固定、在栈/内联。优先用哪种？——长度已知且小用数组，长度未知或要增长用 `Vec`。

## 6.3 切片与切片引用 `&[T]` / `&mut [T]`（S1 / S2 / S3 ✅）

### 什么是切片（slice）

**切片（slice）** 是对一段连续元素的**视图（view）**——它不拥有数据，只是"指向某段数据的窗口"。Rlyeh 提供两种切片相关概念：

1. **切片引用 `&[T]` / `&mut [T]`**：零拷贝胖指针（2 个机器字：`{ 数据指针, 长度 }`），类似 Go 的 slice header、Rust 的 `&[T]`。
2. **动态切片 `v[lo..<hi]`**：从一个容器切出一段，**返回一份新的独立缓冲**（值拷贝）。

> **为什么需要切片**：在 C 里你常写 `int* p = &arr[2]; int len = 5;` 来"指向数组中间的一段"，但 `p` 和 `len` 是分开的两个东西，很容易失配（经典的"指针 + 长度"传递 bug）。Rlyeh 把"指针 + 长度"打包成一个类型 `&[T]`，编译器全程知道长度。

### 切片引用 `&[T]`（零拷贝视图）

```rlyeh
fn sub_len(xs: &[i64]) -> i64 {
    let sub = xs[1..<3];        // 在切片上再切一段（零拷贝子区间）
    sub.len()
}

let xs = [10, 20, 30, 40, 50];
sub_len(&xs);                   // 2：&[i64; 5] 经 unsize coercion → &[i64]，再切片长 2
```

- `&[i64; 5]`（数组的引用）可以自动**收缩（unsize）**成 `&[i64]`（切片引用）——编译器把"长度 5"泛化成"未知长度"，符合直觉。
- `[T]` 本身是 **DST（动态大小类型）**，不能独立存储（你不能写 `let s: [i64];`），必须透过引用 `&[T]` 或 `&mut [T]` 使用。

### 从 Vec 取切片引用

```rlyeh
let v: Vec<i64> = vec![10, 20, 30];
let bp = v.as_slice();         // Vec<i64> → &[i64]（只读视图，零拷贝）
let bm = v.as_mut_slice();     // → &mut [i64]（可变视图，写回原缓冲，零拷贝）
```

> **零拷贝的含义**：`as_slice()` 不复制数据，只是产出一个"指向 v 内部、长度为 v.len()"的胖指针。通过 `bm` 修改，会直接改到原 `v` 的缓冲里。

### 动态切片 `v[lo..<hi]`（值拷贝）

对 `Vec` / 数组用范围下标切片，返回**一份全新的独立缓冲**：

```rlyeh
let v = vec![10, 20, 30, 40];
let part = v[1..<3];           // part: Vec = [20, 30]（新缓冲，和 v 互不影响）
```

- 范围语法同 [§4.5](../guide/04-math-conditions.md)：`lo..<hi` 半开 `[lo, hi)`、`lo...hi` 双闭、`lo<..hi` 左开。
- **越界自动 clamp**：下标超出 `[0, len]` 会被夹到边界；`start >= end` 返回空切片。不会 panic。

### 两种切片的语义区别（重点）

| 写法 | 接收者 | 返回 | 拷贝？ |
|------|--------|------|--------|
| `xs[1..<3]`（其中 `xs: &[T]`） | 切片引用 | 零拷贝子区间（`&[T]`） | 否 |
| `arr[1..<3]`（数组） | 数组 | 全新 `Vec`（值拷贝） | 是 |
| `v[1..<3]`（Vec） | Vec | 全新 `Vec`（值拷贝） | 是 |

> **记忆：** 数组 / Vec 的范围切片 = "复制出一段新数据"；切片引用（`&[T]`）的范围切片 = "在同一个数据上开个新窗口"。需要独立修改用前者，想零开销共享用后者。

### 切片可用方法

`.len()`（长度）、`.first()`（首元素 `Option`）、`.last()`（尾元素）、`.iter()`（遍历）、`.as_ptr()` / `.as_mut_ptr()`（取裸指针，FFI 用）。

## 6.4 综合示例：处理一段数据

```rlyeh
fn sum_range(xs: &[i64]) -> i64 {
    let mut total = 0;
    for x in xs {            // 切片可直接 for 遍历
        total += x;
    }
    total
}

fn main() {
    let arr = [1, 2, 3, 4, 5];
    let s = sum_range(&arr);              // 整个数组当切片传入 → 15
    let part = sum_range(&arr[1..<4]);    // 传入子区间 [2,3,4] → 9
    println(s, part);
}
```

> **C 程序员的视角**：`sum_range(&arr)` 等价于 C 的 `sum_range(arr, 5)`，但 Rlyeh 把长度"绑"在 `&[i64]` 类型里，调用方不用手动传长度，被调方也不会越界读。这是用类型系统消灭"少传/错传长度"类 bug。

---

## 6.5 常见陷阱

| 陷阱 | 说明 | 正确做法 |
|------|------|----------|
| 以为 `arr[1..<3]` 是零拷贝 | 数组/VeC 的范围切片是值拷贝，返回新 Vec | 要零拷贝用 `&arr` 后切片 |
| 想存一个 `[i64]` | `[T]` 是 DST，不能独立存储 | 用 `Vec<T>` 或 `&[T]` |
| `Vec` 忘了 `let mut` 就 push | `Vec` 本身可变但绑定要 `mut` 才能 push | `let mut v = Vec::new();` |
| 越界索引 panic | 运行时越界会安全处理（非 UB） | Rlyeh 比 C 安全，但仍应避免越界 |
