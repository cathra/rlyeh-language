# 4. 数学式条件判断

> 本章目标：掌握 Rlyeh 最直观、也最容易让 C 程序员"哇"一下的语法特性——**比较链**与**集合判断**。它们让条件表达式贴近数学直觉，同时编译器会帮你展开成等价的 C 风格逻辑，不会有性能损失。

---

## 4.1 为什么需要它

在 C 里，判断"x 在 0 到 10 之间"要写成：

```c
if (0 < x && x < 10) { /* ... */ }
```

这很常见，但有两个痛点：

1. **变量 x 要写两遍**，容易笔误写成 `0 < x && x > 10`（逻辑反了但编译器不报错）。
2. **"区间"这个概念在 C 里没有一等表示**，只能拆成 `&&` 组合。

Rlyeh 允许你直接写数学里的连不等式：

```rlyeh
if 0 < x < 10 {}      // 等价于 0 < x && x < 10
if 0 <= x <= 10 {}    // 等价于 0 <= x && x <= 10
if 0 < x <= 10 {}     // 等价于 0 < x && x <= 10
```

> **C 程序员的视角**：`0 < x < 10` 在 C 里是**完全不同的意思**——C 会先算 `0 < x` 得到 0 或 1，再算 `1 < 10` 得到真，整个表达式永远为真（经典坑）。Rlyeh 重新定义了这个语法：**连不等式被编译器展开成 `0 < x && x < 10`**，符合数学直觉。这是 Rlyeh 对 C 语法的一个刻意修正。

---

## 4.2 区间内（正向比较链）

"正向"指运算符方向一致（都用 `<` / `<=`），表达的是**一个区间内的交集**：

```rlyeh
if 0 < x < 10 {}      // 0 < x 且 x < 10  →  0 < x < 10
if 0 <= x <= 10 {}    // 0 <= x 且 x <= 10
if 0 < x <= 10 {}     // 0 < x 且 x <= 10
```

可以三个及以上连写：

```rlyeh
if 0 <= score <= 100 {}   // 0 <= score 且 score <= 100
```

> **编译器怎么做**：比较链本质是一串 `&&` 连接的二元比较，每个中间变量只求值一次（不会重复计算表达式）。所以 `0 < expensive_fn() < 10` 里 `expensive_fn()` 只调用一次。

---

## 4.3 区间外（反向比较链）

"反向"指运算符方向相反（例如 `0 > x > 10` 里先是 `>` 再是 `>`——注意这里两个 `>` 方向相同但语义是"x 比 0 小 且 比 10 大"，数学上不可能同时满足，**所以编译器把它解读为并集**）：

```rlyeh
if 0 > x > 10 {}      // 等价于 x < 0 || x > 10（反向外链 = 并集）
if 0 >= x >= 10 {}    // 等价于 x <= 0 || x >= 10
```

> **为什么反向 = 并集**：数学里"`x < 0` 或 `x > 10`"描述的是"落在区间 **之外**"。Rlyeh 用反向比较链 `0 > x > 10` 表达这个"区间外"语义，展开成 `x < 0 || x > 10`。
>
> **记忆口诀**：正向链（`<...<`、`<=...<=`）→ 区间内（交集 `&&`）；反向链（`>...>`、`>=...>=`）→ 区间外（并集 `||`）。

对照 C：

```c
// Rlyeh: if 0 > x > 10 {}
if (x < 0 || x > 10) { /* ... */ }   // C 必须手写 ||
```

---

## 4.4 集合判断（括号内为离散集合）

`in` 运算符判断"一个值是否属于某个集合"。集合用括号 `(...)` 列出成员：

```rlyeh
if x in (1, 3, 5) {}                  // 等价于 x == 1 || x == 3 || x == 5
if ch in ('a'..<'z', 'A'..<'Z') {}    // 范围元素展开为离散成员（所有小写/大写字母）
if x in (0...10) {}                   // 等价于 x == 0 || x == 1 || ... || x == 10
```

> **C 程序员的视角**：C 里没有"属于集合"的运算符，通常用 `switch` 或者一长串 `||`：
> ```c
> if (x == 1 || x == 3 || x == 5) { ... }
> ```
> Rlyeh 的 `in (...)` 就是这串 `||` 的简洁写法，而且能直接包含**范围**（见 §4.5），C 做不到。

### `not in`（取反）

```rlyeh
if x not in (0..<10) {}    // 等价于 !(x in (0..<10))，即 x 不在 [0,10) 内
```

> **注意**：`not in` 是一个整体运算符，等价于"对整个 `in` 取反"。不要写成 `if not x in (...)`（虽然 Rlyeh 也支持 `not` 一元运算符，但语义上 `not in` 更清晰、优先绑定）。

---

## 4.5 裸范围 = 区间判断

当 `in` 右侧是**裸范围**（没有括号包成集合）时，语义变成**区间判断**（连续区间，而非离散成员）：

```rlyeh
if x in 0..<10 {}    // 0 <= x < 10    半开区间 [0, 10)
if x in 0...10 {}    // 0 <= x <= 10   双闭区间 [0, 10]
if x in 0<..10 {}    // 0 < x <= 10    左开右闭 (0, 10]
```

这里的范围写法和 `for` 循环里的范围一致（见 [§3.3 控制流](../guide/03-basic-syntax.md)），但含义不同：

| 写法 | 作为 `in` 右侧（区间判断） | 作为 `for` 范围（遍历） |
|------|--------------------------|------------------------|
| `0..<10` | `0 <= x < 10` | i 取 0,1,…,9 |
| `0...10` | `0 <= x <= 10` | i 取 0,1,…,10 |
| `0<..10` | `0 < x <= 10` | （`for` 暂以 `..<`/`...` 为主） |

> **关键区别**：
> - `x in (0..<10)` —— 括号包着范围 → **离散集合成员判断**（把 0..9 的每个整数当成员，展开成 `x==0 || x==1 || ... || x==9`）。
> - `x in 0..<10` —— 裸范围 → **连续区间判断**（`0 <= x < 10`，对浮点数也成立）。
>
> 对整数而言两者结果恰好一样，但**对浮点数只有裸范围（区间判断）有意义**——浮点区间里有无限多个数，没法展开成离散 `||`。

### 范围语法速查

| 范围 | 含义 | 是否含下界 | 是否含上界 |
|------|------|-----------|-----------|
| `a..<b` | 半开 `[a, b)` | 含 | 不含 |
| `a...b` | 双闭 `[a, b]` | 含 | 含 |
| `a<..b` | 左开 `(a, b]` | 不含 | 含 |

## 4.6 时间字面量

Rlyeh 内置了**时间字面量**，用 `9am`/`6pm` 这种写法，单位是**分钟**（9am = 540，6pm = 1080，`hour` 取分钟值）。它们可以和比较链、`in` 区间判断组合，特别适合调度 / 时间窗口场景：

```rlyeh
if hour in (9am...6pm) {}             // 工作时间段：540 <= hour <= 1080
if hour not in (6am..<10pm) {}        // 非工作时段；跨午夜自动处理
```

> **为什么方便**：用分钟表示后，时间区间就是普通的整数区间，所以能直接复用 §4.2–§4.5 的全部比较链 / 区间判断语法。你不用自己把 `9:30` 换算成分钟。
>
> **跨午夜**：`6am..<10pm` 即 `[360, 1320)`。`hour not in (6am..<10pm)` 表示该时刻不在这个窗口内（比如凌晨）。如果窗口跨越午夜（如 `10pm..<6am`），Rlyeh 的时间区间判断会正确处理环绕。

## 4.7 综合示例

把多个特性组合起来，写出贴近数学/业务直觉的条件：

```rlyeh
fn classify(hour: i64, temp: f64, tag: i64) {
    // 工作时间且温度舒适
    if hour in (9am...6pm) && 18.0 < temp < 26.0 {
        println("舒适的工作时段");
    };

    // 紧急标签（离散集合）
    if tag in (404, 500, 503) {
        println("服务端错误");
    };

    // 非高峰且非周末标签
    if hour not in (9am...6pm) && tag not in (6, 7) {
        println("空闲");
    };
}
```

---

## 4.8 常见陷阱

| 陷阱 | 说明 | 正确写法 |
|------|------|----------|
| 以为 `0 < x < 10` 是 C 语义 | Rlyeh 已修正为区间，但别和 C 混淆 | 放心用，它就是 `0<x && x<10` |
| 把 `in` 裸范围当集合 | `x in 0..<10` 是区间（连续），不是 `x==0||...` | 要离散集合用 `x in (0..<10)` |
| `not in` 拆成 `not x in` | 虽然能解析，但可读性差 | 用 `x not in (...)` |
| 对浮点数用集合展开 | `(0..<10)` 展开只对整数有意义 | 浮点用裸范围 `x in 0..<10` |
