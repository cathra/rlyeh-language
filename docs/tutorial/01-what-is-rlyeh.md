# 1. 认识 Rlyeh

> 本章目标：读完你应当明白**Rlyeh 是什么、解决什么问题、和 C 有什么不同**，以及**为什么一个只会 C 的程序员值得学它**。不要求你立刻会写代码，先建立心智模型。

---

## 1.1 一句话介绍

Rlyeh 是一门**系统级编程语言**：它编译成和 C 一样接近硬件的原生机器码，能写操作系统、数据库、网络服务这类"基础设施"，但同时把 C 里最容易出错的几件事（内存管理、并发）从"靠程序员自觉"变成了"靠编译器保证"。

> **C 程序员的视角**：你可以把 Rlyeh 想象成一个"会替你检查内存错误、还自带并发原语的 C"。它依然是指针、栈、堆、值语义的世界，但很多在 C 里要运行时才炸的问题，在 Rlyeh 里编译期就被拦下了。

---

## 1.2 为什么还要一门系统语言？

如果你已经会 C，可能会问：**C 能做的事 Rlyeh 都能做，那我为什么要多学一门？**

答案藏在 C 几十年积累的两个老大难问题里：

### 问题一：内存安全靠人，不靠编译器

在 C 里，下面这些写法都能通过编译，但后果严重：

```c
// C：这些都能编译，但都是 bug
int* p = malloc(sizeof(int) * 10);
free(p);
int x = p[0];        // 悬垂指针：读已释放内存（未定义行为）
free(p);             // 双重释放

int* q = NULL;
*q = 5;              // 空指针解引用：段错误

// 缓冲区溢出：C 不会阻止你越界
char buf[4];
buf[10] = 'x';       // 悄悄破坏了别的内存
```

这些问题每年造成大量安全漏洞（Heartbleed、绝大多数浏览器远程代码执行都源于此）。C 编译器**默认信任你**，出了事你自己负责。

Rlyeh 的思路相反：它在编译期追踪"谁拥有这块内存、什么时候释放、有没有人同时读写"，**在编译期就拒绝**那些在 C 里要运行时才炸的写法。

### 问题二：并发靠线程 + 锁，容易死锁/竞态

C 写多线程基本靠 pthread + mutex，而：

- 死锁（两个线程各自拿着对方要的锁）**编译期和运行时都很难发现**；
- 数据竞争（两个线程同时写一个变量）是**未定义行为**，时好时坏最难复现；
- 改一个数据结构常常要重新审计所有加锁点。

Rlyeh 把"actor 模型"做成语言一等公民——并发单元之间**只通过消息通信、不共享内存**，从根本上消除了数据竞争。

## 1.3 Rlyeh 对标谁、长什么样

| 设计目标 | 对标语言 | 在 Rlyeh 里长这样 |
|----------|----------|-------------------|
| 内存安全、零 GC | Rust | 分层内存模型（L0 所有权 → L1 区域 → L2 引用计数 → L3 可选 GC） |
| 编译速度极快 | Go | 模块化增量编译，秒级 |
| 并发模型一等公民 | Erlang / Akka | `actor` 关键字 + 运行时监督重启 |
| 数学式语法直觉 | Python / MATLAB | 比较链 `0 < x < 10`、集合判断 `x in (1, 3, 5)` |

**一句话定位**：Rlyeh = Rust 的安全性 + Go 的编译速度 + Erlang 的并发模型 + 数学的自然表达。

---

## 1.4 和 C 相同的部分（你可以直接复用）

为了降低学习曲线，Rlyeh 刻意保留了大量 C 程序员的直觉：

| C 里你熟悉的东西 | 在 Rlyeh 里 |
|------------------|-------------|
| `int main()` | `fn main()` |
| `printf("x=%d\n", x)` | `println("x=", x)` |
| 值语义（`struct` 拷贝即深拷贝） | 默认仍是值语义（除非你显式用引用） |
| `for (i=0; i<n; i++)` | `for i in 0..<n` |
| `if (a < b && b < c)` | `if a < b < c`（等价，但更直观） |
| 栈上的局部变量 | 仍是栈上局部变量 |
| 函数指针 | 仍是"函数作为值" |
| `switch` | `match`（更强大，能解构数据） |

> **关键认知**：Rlyeh **不是**自动垃圾回收语言（不像 Java/Python/Go 那种"随时有 GC 在后台跑"）。默认情况下它的内存开销和 C 一样——零运行时开销。只有在你**主动选择**引用计数或 GC 层级时才有额外成本。

## 1.5 和 C 不同的部分（你需要重新建立的心智模型）

这些是 Rlyeh 的核心，也是它比 C 安全的原因。**现在看不懂没关系**，后续章节会逐个展开，这里先有个印象：

### (1) 变量默认不可变

```rlyeh
let x = 10;       // 绑定后不能再改（类似 C 的 const int x = 10）
x = 20;           // ❌ 编译错误：x 不可变
let mut y = 10;   // 显式声明可变
y = 20;           // ✅ 可以
```

> **为什么**：不可变是默认，因为大多数变量其实不需要改，而不可变让编译器更容易推理内存安全。C 里 `const` 是可选的，Rlyeh 把"只读"变成默认。

### (2) 内存有"层级"，你按场景选

C 里你只有 `malloc/free`（或自己写内存池）。Rlyeh 提供四层，从零开销到自动管理：

| 层级 | 机制 | 何时用 |
|------|------|--------|
| L0 | 所有权 + 借用（编译期） | 绝大多数场景，零开销 |
| L1 | 区域 Region（批量释放） | 一批同生命周期的对象（如解析一个请求） |
| L2 | 引用计数 `Rc<T>` / `Arc<T>` | 需要多处共享、生命周期不确定 |
| L3 | 可选 GC `Gc<T>` | 极少数图结构等难手动管理的场景 |

### (3) 并发是"发消息"而不是"共享内存"

```rlyeh
actor Counter {
    value: i64 = 0,
    pub fn increment(amount: i64) -> i64 {
        self.value += amount;
        self.value
    }
}
let c = Counter::new();
let r = c.increment(5).await;   // 发消息、等回复（ask 模式）
```

> **C 程序员的视角**：这等价于"C 里一个独立线程跑一个状态机，你给它发消息、它回你结果"，但 Rlyeh 帮你把"消息队列、互斥、崩溃重启"都做掉了。

## 1.6 这门语言现在到什么程度？

本文档描述的是 **MVP（最小可用版本，0.1.0）**。它已经能写真实程序，但**不是所有 Rust 特性都实现了**。本文所有示例都是经过验证、可编译运行的。遇到某个特性标着"规划中 / 暂不支持"，就是 MVP 还没做——文档会在对应章节明确说明，不会让你用到一个还不存在的功能。

> 想知道完整特性清单和已知限制，见 [指南 §13 参考与已知限制](../guide/13-references-limits.md)。
