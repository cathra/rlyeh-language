# 优化级别（-O0 / -O1 / -O2 / -O3 / -Os）

> **状态**：🟢 已落地（2026-11-15）
> **定位**：对齐 C/C++ 的优化级别语义，同时控制 Rlyeh 自身的 MIR 优化流水线与 LLVM 后端。

## 1. 用法

```bash
rlyeh build app.rl -O0 -o app        # 调试：关闭优化
rlyeh build app.rl -O2 -o app        # 常规发布
rlyeh build app.rl -O3 -o app        # 发布级（默认）
rlyeh build app.rl -Os -o app       # 大小优先
rlyeh run app.rl --opt-level=O1     # 等价写法
```

默认级别为 **O3**，与之前的发布级行为一致。

## 2. 级别与流水线

| 级别 | Rlyeh MIR passes | clang 后端 | 典型用途 |
|------|------------------|------------|----------|
| `-O0` | 无 | `-O0` | 调试、最短编译时间 |
| `-O1` | 常量折叠 + DCE | `-O1` | 快速构建 |
| `-O2` | 常量折叠 + DCE + 基础内联 + DCE | `-O2` | 常规发布 |
| `-O3` | 与 O2 相同的 MIR 流水线 | `-O3` | 默认发布级；更强内联/循环向量化交给 LLVM |
| `-Os` | 常量折叠 + DCE | `-Os` | 体积优先 |

Rlyeh 自身的 MIR 优化包括：

1. **常量折叠**：算术/比较/常量条件分支；
2. **死代码消除**：不可达基本块与死赋值；
3. **基础函数内联**：单基本块、无区域操作的函数在调用点展开；
4. 内联后再次 DCE 清理。

O3 的额外强度由 LLVM 承担：函数内联、循环变换、向量化、指令合并等。

## 3. 验证优化级别确实生效

```bash
rlyeh build app.rl --emit ir -O0 -o app.O0.ll
rlyeh build app.rl --emit ir -O3 -o app.O3.ll
wc -l app.O0.ll app.O3.ll
```

O0 的 IR 通常包含更多临时槽与未内联调用；O3 会先做 MIR 内联/DCE，再由 clang 做后端优化。
可执行文件大小也会明显不同（O0 通常更大）。

## 4. 与 `--no-heap` / 缓存的关系

- `-O0` 仍执行类型检查、借用检查与区域检查；只关闭 MIR 优化 passes 和后端优化；
- `--no-heap` 可与任意优化级别组合；IR 无堆守卫在优化前后都生效；
- 缓存键包含优化级别，切换 `-O2`/`-O3` 不会误复用其他级别的产物；
- `--emit ir` 导出的是所选级别的 LLVM IR。

## 5. 当前边界

- Rlyeh 还没有独立的边界检查消除、循环不变量外提、自动向量化 pass；这些由 LLVM 在 `-O2/-O3` 完成；
- `-O0` 主要供调试/定位代码生成问题，不保证运行时性能；
- `-Os` 目前只影响 clang 后端，MIR 不做额外体积优化。
